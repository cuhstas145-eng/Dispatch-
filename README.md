# CargoSync Dispatch Workspace — серверная версия

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/cuhstas145-eng/Dispatch-/tree/cargosync-fullstack-deploy)

Для облачного развёртывания откройте кнопку выше, выберите ветку `cargosync-fullstack-deploy` и задайте `CARGOSYNC_BOOTSTRAP_ADMIN_PASSWORD` в форме Render. Это временный пароль; после первого входа система потребует его заменить. Не публикуйте пароль в GitHub или мессенджере команды.

Полноценный веб-проект CargoSync на базе существующего интерфейса. Сохранены Route Planner, карта, Additional Stops и Quick RPM; добавлены общий Schedule, аккаунты, Admin Panel и серверное хранение Rate Confirmation/POD.

## Что находится в проекте

- `index.html` — весь интерфейс CargoSync: Route Planner, Quick RPM, Schedule, карта, загрузка документов, вход и Admin Panel.
- `app.py` — FastAPI backend, серверная авторизация, права доступа, API, БД и защищённое хранилище файлов.
- `bot.py` — существующий Telegram-бот с новой кнопкой CargoSync Schedule в верхнем ряду клавиатуры. Ссылка открывает сайт сразу во вкладке Schedule.
- `render.yaml` — настройка сервиса Render и ссылка на существующую PostgreSQL базу `cargosync-db`; `Dockerfile` и `docker-compose.yml` — альтернативный запуск на своём VPS.
- `create_admin.py` — безопасное создание первого администратора через интерактивный запрос пароля. В Render первый аккаунт создаётся через секретную переменную `CARGOSYNC_BOOTSTRAP_ADMIN_PASSWORD`.
- `tests/test_api.py` — тесты API, ролей, назначения водителей, документов, конфликтов записи и ограничения попыток входа.

## Возможности

### Пользователи и безопасность

- Отдельный аккаунт каждому диспетчеру, роль Admin / Dispatcher / Viewer.
- Пароли хешируются Argon2id, не хранятся в открытом виде.
- Сессии в HttpOnly cookie; сброс пароля завершает другие сессии.
- Новый сотрудник после первого входа обязан заменить временный пароль.
- Ограничение частых неправильных попыток входа.
- Роли проверяются на сервере, а не только в интерфейсе.

### Диспетчеры и водители

- Администратор сначала создаёт аккаунт диспетчера, затем добавляет его водителей.
- Водителя можно переназначить другому диспетчеру; связанные грузы переходят новому ответственному.
- При удалении аккаунта диспетчера водители и история грузов сохраняются, но становятся неназначенными.
- Нельзя удалить водителя, если у него остались грузы; сначала их нужно переназначить или удалить.

### Schedule и маршруты

- Общая командная сетка Schedule с водителями, сгруппированными под соответствующими диспетчерами.
- Создание груза протягиванием дат, редактирование карточки, поиск пересечений дат и просмотр диапазона PU–DEL.
- Груз связан с единым ID, датами, PU/DEL, водителем/траком, ставкой, статусом и документами.
- Route Planner сохраняет truck location, pickup, additional stops, delivery и расчёт маршрута; Quick RPM остаётся в существующем интерфейсе.
- После входа по Telegram-кнопке `CargoSync Schedule` открывается Schedule, а не Route Planner.
- Общие данные обновляются опросом сервера примерно каждые 3,5 секунды. Конфликт одновременного сохранения не перезаписывает более новую серверную версию молча.

### Документы

- Rate Confirmation и POD загружаются на сервер, доступны участникам с активным доступом к рабочему пространству.
- Допустимы PDF, PNG, JPG/JPEG и WEBP размером до 15 MB на файл; сервер проверяет сигнатуру файла.
- Документы хранятся в приватном каталоге данных, а не в публичной папке сайта.

## Запуск на Windows для локальной проверки

1. Установите Python 3.11 или новее.
2. Распакуйте архив в отдельную папку.
3. Запустите `run_windows.bat`.
4. При первом запуске создайте логин и длинный пароль администратора (минимум 12 символов). Не используйте пароль из примеров или публичного сообщения.
5. Откройте `http://127.0.0.1:8000`.
6. В Admin Panel создайте аккаунты диспетчеров, затем добавьте к ним водителей.

Не открывайте `index.html` двойным щелчком: в таком режиме серверная авторизация, общая БД и загрузка файлов работать не будут.

## Развёртывание на Render (тестовое облако)

В репозитории создана отдельная ветка `cargosync-fullstack-deploy`, чтобы не ломать GitHub Pages на `main`. PostgreSQL `cargosync-db` создан в Render в регионе Frankfurt.

1. В Render откройте **New → Blueprint** и выберите репозиторий `cuhstas145-eng/Dispatch-`.
2. В качестве конфигурации укажите `render.yaml` и ветку `cargosync-fullstack-deploy`.
3. Blueprint использует уже созданную базу `cargosync-db` через `fromDatabase` и создаёт веб-сервис `cargosync-dispatch`.
4. При настройке задайте `CARGOSYNC_BOOTSTRAP_ADMIN_PASSWORD` (не менее 16 символов, уникальный пароль; не добавляйте его в GitHub).
5. Дождитесь успешного деплоя, проверьте `/health`, войдите на выданном HTTPS URL и сразу смените временный пароль.
6. После появления URL добавьте его в переменную `CARGOSYNC_WEBAPP_URL` процесса Telegram-бота как `https://ВАШ-URL/?view=schedule`.

**Ограничение тестового тарифа:** созданная бесплатная PostgreSQL база помечена Render как истекающая **18 ноября 2026 года**. Это не постоянная продукционная база. До этой даты перенесите базу на тариф с постоянным хранением и настройте резервные копии. Бесплатный веб-сервис может засыпать после бездействия.

## Развёртывание на своём сервере с HTTPS через Docker

Понадобится VPS с Docker Engine и Docker Compose, домен и возможность настроить DNS-записи. Профиль `https` поднимает Caddy, который автоматически получает/обновляет сертификат, когда домен указывает на сервер и доступны порты 80/443. Сам CargoSync остаётся доступен только внутри Docker и на loopback-хосте.

1. Загрузите папку проекта на сервер и перейдите в неё.
2. Скопируйте `.env.example` в `.env`.
3. В `.env` установите `CARGOSYNC_SECURE_COOKIES=1`, задайте `CARGOSYNC_DOMAIN=ВАШ-ДОМЕН`, а для Telegram-бота — `TELEGRAM_BOT_TOKEN` и `CARGOSYNC_WEBAPP_URL=https://ВАШ-ДОМЕН/?view=schedule`.
4. Убедитесь, что DNS A/AAAA домена указывает на сервер и порты 80/443 доступны.
5. Запустите web-приложение и HTTPS:

```bash
docker compose --profile https up -d --build
docker compose exec cargosync python create_admin.py
```

6. Войдите на `https://ВАШ-ДОМЕН`. В Admin Panel создайте диспетчеров, затем назначьте им водителей.
7. Чтобы запустить бота одновременно с приложением и HTTPS:

```bash
docker compose --profile https --profile bot up -d --build
```

Кнопка `🗓 CargoSync Schedule` открывает `https://ВАШ-ДОМЕН/?view=schedule`. Если DNS или домен ещё не настроены, сначала запустите веб-сервис локально без профиля `https`, настройте домен, затем включите HTTPS. Не включайте профиль HTTPS до настройки домена.

### Резервное копирование Docker-данных

База и документы хранятся в volume `cargosync_data`. Пример резервной копии на Linux-сервере:

```bash
mkdir -p backups
docker run --rm -v cargosync_data:/data:ro -v "$PWD/backups:/backup" alpine sh -c 'tar czf /backup/cargosync-data.tar.gz -C /data .'
```

Восстановление выполняйте только при остановленном сервисе и после сохранения отдельной копии текущих данных.

## Telegram-бот

- В `.env` задайте `TELEGRAM_BOT_TOKEN` и публичный `CARGOSYNC_WEBAPP_URL`.
- Кнопка `🗓 CargoSync Schedule` появляется в верхнем ряду клавиатуры бота и открывает `/?view=schedule`.
- Команда `/app` тоже выводит кнопку для открытия Schedule.
- Сам бот и веб-приложение запускаются отдельными сервисами, но ведут в одно опубликованное приложение.
- Telegram-кнопка не отключает вход: сотрудник входит со своим аккаунтом CargoSync. Привязка Telegram ID к аккаунту и SSO в этой версии не реализованы.

## Перенос данных из локальной версии

1. В старой локальной версии откройте Admin Panel и экспортируйте резервную копию JSON.
2. В новой серверной версии войдите как администратор и импортируйте JSON.
3. Импорт переносит метаданные водителей и Schedule; аккаунты/пароли создайте через новую Admin Panel. Документы из локального IndexedDB необходимо прикрепить повторно, если отдельные файлы не сохранены.
4. После импорта проверьте владельцев водителей. Совпавшие логины сопоставляются с аккаунтами по username; иначе водители останутся неназначенными.

## Данные и резервные копии

- При локальном запуске без `DATABASE_URL` данные хранятся в SQLite в каталоге `data`.
- При запуске на Render переменная `DATABASE_URL` направляет приложение в PostgreSQL; документы хранятся в базе, а не в эфемерной файловой системе контейнера.
- Для резервной копии используйте согласованную копию базы и директории `documents`; не удаляйте volume при обновлении приложения.
- Не храните `.env` в репозитории: он содержит токен Telegram и конфигурацию. Архив использует `.gitignore` для `.env`, базы и загруженных файлов.

## Проверки и ограничения

Запустить API-тесты локально можно командой `pip install -r requirements-test.txt` и затем `pytest -q`.

- Выполнены Python compile checks и API-тесты: авторизация, смена временного пароля, роли, назначение/переназначение водителей, защита от изменения чужих грузов, загрузка/скачивание документов, rate limit и конфликты версий.
- Render-конфигурация использует PostgreSQL; у бесплатной базы ограниченный срок действия. Для постоянной рабочей эксплуатации нужен оплачиваемый/постоянный тариф, регулярные бэкапы и мониторинг.
- Автообновление Schedule сейчас опрашивает API, а не использует WebSocket.
- Маршрутизация и геокодирование зависят от внешних картографических сервисов; расчёт не является truck-legal routing.
- Веб-приложение публикуется через Render HTTPS URL. GitHub Pages `main` остаётся прежним, пока новый сервер не пройдёт проверку. Не используйте бесплатную БД как постоянное хранилище рабочих грузов.
